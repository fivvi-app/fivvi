## Context

`PRODUCT.md §76` specifies PostgreSQL and lists the core entities. The data is relational (workspaces, members, sessions, occurrences, bookings, workouts, sets). Correctness depends on database features: transactions and row locks for booking capacity (R3), Row-Level Security for tenant isolation (ADR-006), `timestamptz` for time (ADR-012). Client data may include health information, so it must stay in the EU (`ROADMAP.md §2`, principle 7).

## Decision

- **PostgreSQL** in an **EU region**. The provider and region are set by ADR-011.
- **Drizzle ORM** for schema definitions and queries, in `packages/database`.
- **Versioned SQL migrations**, generated by Drizzle Kit, reviewed as SQL and committed. Migrations run **forward-only**; production is migrated only from `main`.
- RLS policies, triggers and anything Drizzle can't express are written as plain SQL in the same migrations.
- A **seed** script creates realistic demo data (used locally, in previews and in tests). It never contains real client data.

## Consequences

- **Positive:** SQL-first: Drizzle's queries stay close to SQL, so agents and reviewers can reason about the exact statements. That matters for RLS and locking.
- **Positive:** reviewed SQL migrations make schema changes visible in PRs.
- **Negative:** Drizzle is younger than Prisma; some advanced features need raw SQL. Accepted, because we want SQL anyway for RLS.
- **Negative:** forward-only migrations mean a mistake is fixed by a new migration, not a rollback. Destructive changes use expand → migrate → contract.
- **Follow-ups:** E004 sets up the schema, migrations and seed in M1; `TESTING.md §3` requires a migration test and an "RLS policy exists" check for every business table.

## Alternatives considered

| Option | Why not |
|---|---|
| Prisma | Heavier runtime and its own query engine; RLS needs per-request session settings, which are awkward with Prisma; raw SQL escape hatches are more common |
| Kysely only (query builder) | Good fit for SQL, but no schema/migration story built in; Drizzle gives both |
| MySQL / SQLite | No RLS; weaker time-zone types; spec says PostgreSQL |
| Document database | The domain is relational and needs transactions across rows |
