# High-risk paths (ADR-016, ADR-021, spec #292). A PR that changes, adds, deletes or renames any of these is high-risk.
# scripts/risk.sh reads this file; this file is itself owner-only (scripts/), so agents can't loosen it.
#
# Who merges a high-risk PR depends on its group: a group declared on an `@agent-queue <group>` line is agent-queueable
# (an agent adds the PR to the merge queue when the whole merge gate holds, and records it in the PR body); every other
# group is owner-only, and so is any group added later. A declared group needs a path rule below, and a line in any
# other shape is an error (fail closed). The `@agent-queue` lines end at pilot setup, before the first real personal
# data enters production (ROADMAP.md, pilot setup checklist): remove them all then. The `billing` line ends earlier
# if production gets a live payment-provider key first: remove it before that key is set, because payment code is only
# agent-queueable while payments run in the provider's test mode. `guardrails` (core), `legal` and `product-docs` are
# never declared: they stay owner-only.
#
# `@except <group> <pattern>` carves paths out of an owner-only rule: a file that matches it is skipped by every rule
# of that group, so a broad rule (`guardrails /scripts`) keeps catching every new file while the files listed as
# `tooling` below belong to the agent-queueable group instead.

@agent-queue tenant-data
@agent-queue health-notes
@agent-queue dependencies

# One rule per line: <group> <pattern>. Patterns are case-insensitive globs; `*` matches within one path segment. A
# pattern that starts with `/` is anchored at the repo root, any other matches at every depth. A pattern also matches
# everything below it.
